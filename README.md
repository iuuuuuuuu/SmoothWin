# SmoothWin

> Windows 用久了越来越卡的**常驻托盘**缓解工具。单文件、零依赖，用系统自带的 .NET Framework 4.8 运行时，编译产物就是一个 exe。

## 一、先说结论：Windows 为什么"用久了就卡，非得物理重启"

这是这个项目存在的理由，所以放在最前面。三件事叠加在一起：

### 1. 用户态"内存清理"碰不到内核池

市面上大多数"内存优化"工具做的事，是遍历进程调用 `EmptyWorkingSet`。它只能把**用户态工作集**里的页面挪走，挪到"已修改页"列表里等写盘。
真正会随长时间运行无限膨胀的那部分 —— **内核分页池 / 非分页池**（GPU 驱动、文件系统过滤驱动、网络栈、各种内核对象）—— 用户态**一个字节都回收不了**。

### 2. 清理动作本身会制造"硬缺页风暴"

`EmptyWorkingSet` 把页面推进已修改列表 → 需要写盘 → 页面被换出 → 进程一访问就硬缺页换回来 → 工具看内存又高了，再清理一次。
实测：一次整理释放 4498 MB，两分钟后硬缺页飙到 **174694 次/秒**。这是个**自我强化**的循环，越清理越卡。

### 3. 快速启动让"关机再开机"变成了假的

`HiberbootEnabled=1`（快速启动）时，"关机"只是把内核状态**休眠**进 `hiberfil.sys`，下次开机直接恢复 —— 内核池里的碎片和泄漏**原封不动带回来**。
所以"重启一下就好"里的"重启"，只有**真正断电重启**（关闭快速启动 / 选"重启"而不是"关机"）才管用。

**结论：这类卡顿能缓解，但不能靠"更勤快地清理内存"解决。** 正确做法是——**只在系统真的空闲时做最小幅度的整理**，并且把"是不是又开始了"这件事**如实记录下来**，而不是每隔几分钟无脑清一遍。

## 二、SmoothWin 做了什么

一个托盘常驻的小程序，**只做"没人用的时候"的那部分工作**，其余时间只观察、不打扰。

### 监测（每 5 秒一次，全部只读）
| 指标 | 说明 |
| --- | --- |
| 提交内存 / 提交上限 | 触发整理的主要判据 |
| 可用内存、待机缓存、已修改页 | 判断"内存去哪了" |
| 内存压缩 | Windows 10 的压缩存储占用 |
| 非分页池 / 分页池 | 内核池，**这才是长期运行真正会涨的东西** |
| 硬缺页/秒、DPC%、中断%、磁盘队列 | 卡顿的直接体感指标 |
| 进程/线程/句柄总数 | 泄漏的宏观指标 |

### 整理（默认自动，且极其克制）
- 只在**空闲**时做：有窗口正在用的进程跳过、正在跑任务的跳过、冷却期内的跳过
- 只对"没用但占着内存"的后台进程做工作集整理
- 冷却时间默认 900 秒，最小可整理量按物理内存自适应
- 所有阈值都**按物理内存自动换算**，不写死数字（换台机器一样能用）

### 记录与提醒
- 显卡驱动崩溃（事件 4101 TDR）、WHEA 硬件错误计数
- 内存**增长追踪**：找出"一直在变大"的进程
- ★ **绝不会叫你关掉正在用的程序**（node、firefox、编辑器、虚拟机……）。提醒的措辞是"保存好工作后重启它一次"，而不是"请关闭它"
- ★ **增长提醒忽略名单**：点气泡就能"以后别再提醒这个程序"，或者设置"提醒 3 次后自动静音"

### 启动项可视化开关
- 把开机自启项列成表格：名称 / 状态 / 占用内存 / 位置 / 启动命令
- 可以在这里**启用 / 禁用 / 结束进程 / 打开所在位置**
- ★ **它绝不自动禁用任何一项。** 程序只是把开关摆在你面前，按不按、按哪个，永远由你决定
- 禁用只是写启动开关，程序本身不会删，随时能开回来

### 手动退出就是真的退出
- 点「退出」会在数据目录留一张"手动退出记录"
- 计划任务到点拉起的新实例看到这张记录会**立刻静默退出**（不复活、不占内存、不弹窗）
- 下次你自己双击启动、或重启电脑后，记录自动失效
- 反过来，**被强杀 / 假死**的实例会被看门狗接管，不会变成没人管的僵尸

## 三、编译

### 本地（Windows 10/11 自带，不需要装任何东西）

```cmd
build.cmd
```

或者手写一行：

```cmd
%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe /nologo /target:winexe /optimize+ /platform:anycpu /codepage:65001 /out:SmoothWinTray.exe SmoothWinTray.cs
```

> ⚠️ `/out:` 和源文件路径**都用反斜杠**。写成正斜杠会得到 `error CS1504: 源文件"…"未能打开`。

### GitHub Actions

推送到 `main` 或手动 `workflow_dispatch` 会自动编译、跑一次冒烟测试，并把 exe 作为 artifact 上传。见 [`.github/workflows/build.yml`](.github/workflows/build.yml)。

## 四、使用

```
SmoothWinTray.exe                  常驻托盘（双击图标开状态窗口）
SmoothWinTray.exe --install        安装开机自启 + 5 分钟自愈看门狗（需要管理员）
SmoothWinTray.exe --uninstall      卸载计划任务
```

### 命令行 / 自检模式

全部**不弹窗口、不驻留**，结果写到数据目录的 `cli-<模式>.txt`（可以用 `--out 文件` 指定）：

| 模式 | 作用 |
| --- | --- |
| `--report` | 打印完整状态报告 |
| `--trim` | 立即整理一次并报告释放量 |
| `--selftest` | 自检注册表 / 性能计数器 / 事件日志 / API 可用性 |
| `--devices` | 检查有无缺驱动的设备 |
| `--startup` | 列出开机自启项 |
| `--fix` / `--restore` | 应用 / 回滚系统级修复（快速启动、TdrDelay 等） |
| `--quit` | 让运行中的托盘按"手动退出"正常退出 |
| `--quitstate` | 查看"手动退出"记录还在不在 |
| `--clearmark` | 清掉"手动退出"记录 |
| `--uicheck` | 状态窗口排版自检（按钮有没有被裁、页脚有没有压住正文） |
| `--startupui` | 自启项窗口自检（内容 + 启用/禁用注册表往返） |
| `--leaktest` | 增长提醒忽略名单读写 + 自动静音自检 |
| `--statusshot` / `--startupshot` / `--settingshot` | 把窗口截图存到数据目录 |

数据目录：`%LOCALAPPDATA%\SmoothWin`（配置 `tray-config.ini`、日志 `tray.log`、心跳 `heartbeat.log`）。

## 五、设计原则（也是几条硬规矩）

1. **不碰正在用的东西。** 有窗口在用、正在跑任务、在冷却期内的进程一律跳过。
2. **不自动禁用任何自启项、不自动结束任何进程。** 只提供开关，决定权在用户。
3. **提醒必须给出可执行的下一步。** 说"它在变大"而不说怎么办，等于没说。
4. **绝不要求用户关闭正在使用的程序。**
5. **所有阈值按物理内存自适应**，不针对某一台机器写死。
6. **自检先行。** 每个界面和每条关键逻辑都有对应的 `--xxx` 自检模式，改完自己先跑一遍。

## 六、运行环境

- Windows 10 1903+ / Windows 11（自带 .NET Framework 4.8）
- 需要管理员权限的功能（自启任务、系统级修复、部分注册表写入）会单独提示；其余功能普通权限即可
- 无需安装、无需运行时、无第三方依赖、不联网
