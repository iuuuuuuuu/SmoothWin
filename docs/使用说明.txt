SmoothWin 常驻内存管家  使用说明
======================================================================

这是什么
--------
一个常驻后台的托盘小程序（SmoothWinTray.exe），专门对付 Windows
「开机用久了越来越卡、只有彻底重启才恢复」这类问题。

  单文件、免安装、不写驱动、不改系统文件、不联网、不上传任何数据。
  编译目标 .NET Framework 4.8 —— Win10 1903 及以上、Win11 全都自带，
  拷到别的电脑直接双击就能跑。

  它是通用软件：阈值按本机物理内存自动设定，不针对任何特定机型。
  提交阈值 / 内存压缩阈值 / 只整理大于 / 非分页池告警线 四项全都按容量算，
  换机器或加内存后自动重算（详见下文第 1 条）。
  「系统优化（fix）」里有两项是「按需启用」的：连接待机项要先检测本机
  是否真的在用连接待机；MPO 项要先检测本机近 30 天是否真的出现过显卡
  驱动崩溃。不满足就跳过，不会乱改别的电脑的设置。


怎么启动
--------
双击  SmoothWinTray.exe
  任务栏右下角出现一个小圆点图标 = 已经在后台运行了。
  图标颜色含义：
    绿色  = 内存健康
    黄色  = 提交内存超过阈值
    红色  = 提交内存超过 90%，或内核非分页池超过告警线（危险）
             告警线 = 512 MB + 物理内存×3%（夹在 512~4096 MB）
             4GB→635  8GB→758  16GB→1003  32GB→1495  64GB→2454
    灰色  = 已暂停自动整理

  想让它每次开机自动运行，见下面「开机自动启动」一节。


托盘右键菜单
------------
  打开状态窗口      —— 看当前内存、池、实时压力、系统设置、事件统计
  立即整理内存      —— 手动触发一次
  暂停自动整理      —— 临时关掉自动整理（图标变灰）
  设置…             —— 改阈值（每项可勾「自动」按本机内存算）、开关自动整理、
                       开关开机自启
   检查有问题的设备… —— 扫描驱动没装好的硬件，说明影响、给出定位方法
  看看开机自启项…   —— 列出所有开机自启项，按内存占用排序
  看看后台应用…     —— 看每个程序带起的子进程、各自占多少内存、跑了多久，
                       可以只关某一个子进程（不用整个程序关掉）
  复制当前报告      —— 把状态报告全文复制到剪贴板，方便贴给别人看
  打开历史记录(CSV) —— 用 Excel 看内存随时间的变化曲线
  打开运行日志      —— 排查用
  打开配置目录      —— 数据文件所在文件夹
  以管理员身份重新启动 —— 需要改系统设置时用
  退出

  单击 / 双击托盘图标 = 直接打开状态窗口。
  点一下弹出的通知 = 同样打开状态窗口（通知里写不下的完整建议在里面）。

   状态窗口（新界面，不再是纯文本一大堆）：
     顶部：状态圆点 + 一句话结论 + 更新时间/已运行时间/权限，右上角「自动刷新」；
     四张指标卡：可用内存 / 提交内存 / 换页压力 / 系统负载，
                 大字号数值 + 颜色（绿=正常 黄=留意 红=要处理）+ 进度条；
     左下「系统设置」：快速启动 / TdrDelay / 开机自启 / 设备驱动 / 挂起重启；
     右下「最近情况」：24 小时显卡驱动崩溃、WHEA 硬件错误、待机缓存、
                       内存压缩、进程/线程/句柄；
     底部「结论卡」：只有需要你动手时才展开详细步骤，平时就一句话「一切正常」。
     最下面一排按钮：
       立即整理 / 暂停·恢复 / 设置… / 详细报告 / 打开日志 /
       设备检查 / 自启项 / 后台应用 / 复制报告 / 隐藏窗口
       详细报告 = 旧的纯文本全文（想细看或者贴给别人看时用）。
       复制报告 = 直接把全文复制到剪贴板。

   ★ 窗口不会卡住了：所有采样和拼装都在后台线程做，界面只负责贴数字。
     旧版每秒被自己的报告生成堵 1.5 秒，点通知进来会显示「未响应」；
     实测现在界面最大停顿 79~125 毫秒（超过 1000 毫秒才会「未响应」）。
   状态窗口右上角「自动刷新」复选框：
    勾选（默认）= 每秒刷新一次数字；
    取消勾选   = 画面固定不动，方便慢慢往下翻看。
  无论勾选与否，窗口都不会再把你拽回顶部（旧版这个毛病已修）。


它到底做了什么（五件事 + 三个查看工具）
----------------------------------------

0) 先自动处理，实在不行才提醒你
   这条是总原则：程序会先自己动手，只有在「它确实没权限、没办法」的
   时候才会弹通知，而且通知里一定写清楚该干什么。

    通知出现的条件（不满足就完全静默）：
      · 连续 12 次采样（约 1 分钟）都处于压力中，才算「持续」——
        打开程序、切窗口时硬缺页本来就会瞬间冲高，单次超标不报警；
      · 同一类提醒 30 分钟内只弹一次（不会反复弹同一件事）；
      · CPU / 磁盘 / 驱动型还要求「你已经 10 分钟没动键盘鼠标」才弹——
        你正在用电脑时它只记日志，等你离开才提醒（内存型不受此限制，
        因为内存真见底时人在不在用都会卡）；
      · 内存型还要求已经自动深度整理过 2 次、压力仍然没降下来。

    ★ 阈值特意设得比较宽容，就是为了不打扰你：
      CPU 要持续 >= 95% 才算压力（默认 95%，本机常驻编译/虚拟机也不误报）；
      硬缺页要 >= 20000 次/秒（正常几到几千，尖峰不算）。
   通知长这样（按四类不同）：
     标题  内存持续吃紧，看一下怎么缓解
     正文  已自动深度整理 2 次仍未缓解。点这里看不关程序也能缓解的办法。
   点一下通知 = 直接打开状态窗口，最上面就是「该干什么」的完整步骤。
   会列出占用最多的几个程序（只列你自己装的程序，不会拿
   Memory Compression、dwm 这类系统进程来糊弄你）。

   ★ 它不会叫你「关掉某个程序」。
     你正在用的 firefox / node / 虚拟机这类程序，程序一律只给
     「不关也能缓解」的动作（详见下面第 3 条末尾）。

   想让它连这种通知都不弹：设置里关掉「压力提醒」即可。


1) 自动整理内存（默认开启）
   每 5 秒采样一次；当出现下面任一情况时自动触发一次整理：
     · 提交内存占比 >= 阈值（默认按物理内存自动设定，见下表）
     · 内存压缩 >= 阈值（默认取物理内存的 5%，夹在 512~4096 MB）
   整理动作 = 对后台进程调用 EmptyWorkingSet，把闲置进程的工作集
   还给系统（不结束任何进程、不丢数据）。
   触发后有 1800 秒冷却，同一个进程两次整理之间还要再隔 900 秒，
   不会反复整理（反复整理 = 反复制造硬缺页，那是帮倒忙）。
   实测效果：一次可释放 1.7 ~ 5.4 GB 可用内存。

   ★ 只整理「没在用」的进程：
   前台窗口、系统关键进程（System/csrss/dwm/lsass/winlogon/svchost）、
   以及正在跑任务的进程（编译 / 渲染 / 虚拟机 / 你刚操作过的）
   全部主动跳过。整理结果里会写清楚跳过了几个、为什么跳。

   阈值按物理内存自动设定（自动调优，可关）—— 换机器/加内存自动重算：

     物理内存      提交阈值   内存压缩阈值   只整理大于   非分页池告警线
     <= 4 GB        72%        512 MB        64 MB         634 MB
     <= 8 GB        78%        512 MB        64 MB         757 MB
     <= 16 GB       82%        819 MB        64 MB        1003 MB
     <= 32 GB       85%       1638 MB        81 MB        1495 MB
     > 32 GB        88%       3236 MB       161 MB        2453 MB

   四项的算法（都是「本机物理内存」的函数，不是写死的数字）：
     · 提交阈值     阶梯取值 72 / 78 / 82 / 85 / 88%
     · 内存压缩     物理内存 × 5%，夹在 512 ~ 4096 MB
     · 只整理大于   物理内存 × 0.25%，夹在 64 ~ 512 MB
                    （4GB 机器上 150MB 已是大进程，64GB 机器上遍地都是，
                      按容量算才不会在小机器漏整理、在大机器瞎整理）
     · 非分页池告警线  512 MB + 物理内存 × 3%，夹在 512 ~ 4096 MB
                    （老版本写死 3072 MB：4GB 机器一辈子碰不到，
                      64GB 机器上驱动泄漏到 3GB 其实还早得很）

   设置窗口里，前三项各自带一个「自动」勾选框：
     · 勾上「自动」= 按本机物理内存算（框里的数字变成只读灰底，
                     显示的仍是当前真正生效的值，能看清、只是改不了）；
     · 取消勾选   = 固定成你自己填的数字，程序不再覆盖它。
   配置文件里对应写的就是 auto 三个字母，所以换机器后不会把
   上一台机器算出来的数字带过去（这正是「通用」的关键）。

   从老版本升级：如果某项的值恰好等于「按本机内存应该算出来的值」，
   就认为它本来就不是你手填的，自动切回「自动」；MinTrimMB 还额外
   认 150（旧版本的出厂默认），同样切回自动。你自己填的其它数字一律保留。

   ★ 增长提醒的两个「别再烦我」开关（设置窗口最下面）：
     · 增长提醒忽略名单
       填进程名（逗号分隔，如 node,chrome,Code），这些程序以后一律不提醒。
       留空 = 都提醒。
     · 同一程序提醒几次后自动静音（0 = 不静音）
       默认 3 次。同一个程序被点名 3 次之后，程序自己把它写进上面的
       忽略名单，以后彻底安静——不需要你手动去填。
     更省事的办法：收到「发现越用越大的程序」那条气泡时，直接点它，
     会问一句「以后不再提醒「node」的内存增长吗？」，点「是」即可。
     想反悔：设置窗口里把那行名字删掉就恢复提醒。


2) 从待机恢复时立刻整理一次
   待机恢复瞬间是显卡驱动崩溃的高发点，恢复时立即清一次工作集
   能明显降低那一下的卡顿概率。

3) 实时压力监测（判断「卡」到底卡在哪）
   状态窗口和 --report 里的「实时压力」段给出这些数字：

     · 硬缺页/秒（Pages Input/sec）
       必须去读硬盘才能满足的缺页。这个数字持续偏高 = 内存真的不够，
       系统正在拿硬盘当内存用，这就是卡顿最直接的证据。

     · 系统负载：CPU %  磁盘繁忙 %（队列 N，N MB/s）
       CPU 一直被某个程序占满、或者硬盘一直排队，同样会让整机发卡，
       而且这两种情况「整理内存」完全帮不上忙。
       注意：磁盘繁忙率在 NVMe 上可能超过 100%（多队列并行），
       所以判定「磁盘卡」还要同时看队列长度（要 >= 2）。

     · DPC %  /  中断 %
       内核在驱动里自旋的时间占比。CPU 占用看着不高、但机器发卡，
       通常就是这里偏高——多半是某个驱动的问题。

     · 磁盘读写 : 谁在读盘
       列出当前读写量最大的几个你装的程序（MB/s）。
       磁盘卡的时候，这一行直接告诉你是谁在读写。

   程序把卡顿分成四类：内存型 / CPU 型 / 磁盘型 / 驱动型，
   哪一类超标就按哪一类给建议——四类的处理办法完全不同。

   超标时的处理顺序（见上面第 0 条）：
     先自动深度整理 → 还不行才提醒你，并附上「怎么办」。

   ★ 只有「内存型」才会触发自动深度整理。
     CPU 跑满或磁盘排队时去清工作集毫无用处，反而会制造额外读盘，
     所以那种情况程序只提醒、不乱动。

   ★ 四类建议都不要求你关掉正在用的程序，给的是「不关也能缓解」：
     内存型 → 判断标准是「可用内存」而不是「占用多少」，
              谁在越用越大就把它重启一次（不用卸载、不用停用）；
     CPU 型  → 把后台任务的优先级调成「低于正常」，任务照跑但不抢前台；
     磁盘型 → 把 Windows 更新 / 网盘同步 / 下载 / 杀毒扫描「暂停」（不是关）；
     驱动型 → 装芯片组和显卡驱动，外接设备拔掉试一次看 DPC 降不降。

   ★ 为什么现在不会「一直提示我」了（旧版的毛病，已修）：
     · CPU 阈值 90% → 95%（编译、跑虚拟机时本来就常年 90% 上下）；
     · 连续确认 4 次 → 12 次（约 1 分钟），瞬时尖峰不再算数；
     · 同一类提醒 30 分钟内不重复（旧版压力一解除就能马上再弹）；
     · 你正在用电脑时不弹 CPU/磁盘型提醒，等你离开再说；
     · ★ 就算你离开了、CPU 一直被占满，只要占 CPU / 磁盘的是「你自己的
       程序」（node、firefox、编译、虚拟机…），也照样不弹——因为那是你
       在干活，不是故障。只有系统进程长期占满才值得提醒你。
       这种「判定为正常在用」只在日志里记一笔（每 10 分钟最多一行）。

4) 进程增长追踪（找出到底是谁在漏）
   每 5 分钟把所有进程按名字聚合，和基线快照对比，算出每个程序的
    增长超过默认 500 MB/小时 且总量增加 50 MB 以上，并且连续 3 次
    采样（约 15 分钟）都点名同一个程序，才会提醒，直接点名是哪个程序。

    ★ 阈值故意调高：node / firefox / qemu 这类程序正常用着就会以
      几百 MB/小时 的速度变大，那是正常的（缓存、堆增长），不是泄漏。
      只有明显异常（比如一小时涨 1 GB 以上）才值得提醒。

   注意：对比窗口不足 30 分钟时只报增长量、不换算「每小时」，
   因为几分钟的波动外推成小时会得出很离谱的数字（没有参考价值）。

   基线是长期锚点，存在 <数据目录>\proc-baseline.csv。基线满 12 小时
   才会滚动更新一次，这样它才能看出「一天里慢慢变大」这种真泄漏，
   而不是被每 5 分钟一次的刷新冲掉。所以隔几小时跑一次
     SmoothWinTray.exe --report
   也能看到同样的对比结论，不用一直开着托盘。


查看工具 A：检查有问题的设备（菜单「检查有问题的设备…」）
    程序不能替你装驱动，但能告诉你「到底缺哪个驱动」。
    扫描的是 Windows 自己的设备状态（CM_Get_DevNode_Status），
    也就是设备管理器里那些带黄色感叹号的项。

    输出分两类：
      [影响]  USB 控制器、PCI 桥、网卡、音频、存储控制器、蓝牙这类
              —— 它们的驱动反复加载失败会实打实拖慢系统
      [忽略]  没插的 U 盘、没连的蓝牙耳机、键鼠显示器这类外设
              —— 不影响性能，列出来只为让你心里有数

    ★ 只说明���题，不替你下载：
      程序会告出这些设备是什么、问题代码是什么意思、
      为什么会拖慢系统，以及怎么自己定位（设备管理器 → 属性 →
      详细信息 → 硬件 ID，记下 VEN_ / DEV_ 去搜或按机型找）。
      它不会给你厂商直链、不会替你下驱动、也不会改你的系统。
      窗口底部只有「打开设备管理器」和「重新检查」两个按钮。

    顺带检测「挂起重启」：Windows 更新或驱动安装留下「重启后才生效」
    的改动时，系统自己不会提醒你，这里会写出来。
    如果机器已经连续运行超过 3 天还没重启，会弹一次提醒（3 天内不重复）。

查看工具 B：开机自启项（菜单「看看开机自启项…」/ 状态窗口的「自启项」按钮）
    把「降低常驻负载」这件事变成看得见、点得动的表格。
    扫描 HKCU/HKLM 的 Run 项 + 启动文件夹，列出全部自启项，
    每项显示：名称 / 状态（运行中·已启用·已禁用）/ 占用内存 / 位置 /
    启动命令，按占用从大到小排。

    实测本机：26 项，正在运行 16 项，合计约 1.8 GB 内存。
    ——这就是「开机久了越来越卡」最直接的一块来源。

    表格下面一排按钮，选中一行后操作：
      禁用自启 / 启用自启   直接改「启动」开关（等同任务管理器里的禁用）
      结束进程              把当前正在运行的这个程序关掉（会先确认）
      打开位置              在资源管理器里定位它的 exe
      刷新                  重新扫描一遍
      以管理员身份重新打开   要动「所有用户」那一组时用
      关闭

    ★ 它绝不自动禁用任何一项。
      程序只是把开关摆在你面前，按不按、按哪个，永远由你决定。
      （这类工具擅自帮你关自启，很容易把远程控制、安全软件
        一起关掉，那是很危险的。远程控制类、安全软件、显卡相关
        建议一律保留。）
      点「禁用自启」后它只做一件事：写系统的「启动」开关，
      程序本身没删、没卸载，随时能在同一个窗口里点「启用自启」开回来。

    也可以照旧用任务管理器：Ctrl+Shift+Esc →「启动」选项卡 → 右键禁用。


查看工具 C：后台应用（菜单「看看后台应用…」/ 状态窗口的「后台应用」按钮）
    解决的是另一个看不见的浪费：一个程序往往不止一个进程。
    浏览器、编辑器、远程控制、下载器都会「一个主程序带一串子进程」，
    任务管理器里只看到一个名字，实际内存是几十个进程加起来的。

    这个窗口把它们摊开成一棵树：
      根行 = 一个顶层程序，例如  firefox · 合计 8679 MB · 38 个进程 · 12 小时 20 分
      子行 = 它带起来的每一个进程，例如  firefox · 1737 MB · pid 35624 · 12 小时 20 分
    点左边任意一行，右边显示它的全部信息：
      名称 / PID / 父进程 / 启动时间 / 已运行 / 内存（含整个程序组合计）/
      CPU 累计 / 磁盘累计 / 线程数 / 有没有窗口 / 子进程数 / 程序位置 /
      以及一句「这是啥」（内置 30 多条常见进程名的通俗解释）。

    标题行会写：现在共几个顶层程序、全部合计占多少内存。
    实测本机：17 个顶层程序、396 个进程、合计约 28 GB。

    顶部工具：
      筛选框     输入名字就只剩匹配的行（父行不匹配但子进程匹配的会保留）
      只看 100 MB 以上   勾上就只看大块头
      每 5 秒自动刷新    勾上就自己更新（不勾就固定不动，方便慢慢看）
      排序       占内存最多 / CPU 用得最多 / 按名字 / 最近才启动的

    选中一行后可以做的事（下面一排按钮，或者直接右键那一行）：
      结束这个进程    只关这一个（按 PID 关，绝不会误伤同名的别的进程）
      结束整个程序组  把这个程序带起来的整串子进程一起关掉
      关闭窗口        让它自己正常关（相当于点它的右上角 ×，会提示保存）
      切到前台        把它窗口调到最前面
      打开所在位置    在资源管理器里定位它的 exe
      复制这一行的信息 / 复制清单 / 导出清单…   贴给别人或存档
      开机自启项      跳到上面那个自启项表格

    ★ 安全线（和自启项窗口一样严）：
      · 系统组件（explorer、winlogon、csrss、服务主机等）永远不给关；
      · 本程序自己不给关；
      · 远程控制类、安全软件、显卡相关同样在保护名单里；
      · 结束前会问你一次，不会闷声动手；
      · 只在这个窗口里点，它不会自己去关任何东西。

    最实用的两个场景：
      1) 某个程序关掉了但内存没降 —— 在这里找到它的残留子进程，单独关掉。
      2) 一个程序卡住但不想丢别的窗口 —— 只关卡住的那个子进程。

系统优化（fix / restore）
-------------------------
对若干注册表项做可逆修改。第一次修改前会自动把原值备份到
   <数据目录>\sysfix-backup.ini
随时可以一键还原成修改前的样子。

  1. 关闭快速启动  HiberbootEnabled = 0
     作用：「关机」变成真正的完全关机，内核池碎片和驱动错误状态
     不再被 hiberfil.sys 带到下一次开机。
     代价：开机会慢几秒（正常现象）。

  2. 延长显卡 TDR 超时  TdrDelay = 10 秒
  3. 延长显卡 TDR 超时  TdrDdiDelay = 10 秒
     作用：显卡驱动偶尔响应慢时，从默认 2 秒放宽到 10 秒，让它有机会
     自己缓过来，而不是被强行复位导致画面闪黑、系统卡死。

  4. 崩溃后自动重启  AutoReboot = 1
     作用：万一真蓝屏，机器自动重启而不是停在蓝屏界面等你按电源。

  5. 关闭连接待机(Modern Standby)  PlatformAoAcOverride = 0
     作用：只在检测到本机正在使用 S0 连接待机时才设置（近 168 小时内有
     Kernel-Power 506 事件）；台式机/传统睡眠的电脑会自动跳过这一项。

  6. 关闭显卡深度省电  EnableUlps = 0
     作用：在显卡驱动的注册表里关掉 ULPS（超低功耗状态）。显卡在省电
     与唤醒之间反复切换，正是「显示器驱动程序已停止响应」的高发点。
     说明：只处理驱动里确实存在 EnableUlps 的显卡；NVIDIA / Intel 没有
     这个键，会自动跳过，不会误伤。

  7. 关闭 MPO 多平面覆盖  OverlayTestMode = 5
     作用：只在检测到本机近 30 天出现过显卡驱动崩溃（Display 事件 4101）
     时才设置。MPO 是 DWM 的一种合成加速，遇上虚拟显示器 / 远程控制
     软件时容易和显卡驱动打架，关掉能明显减少 4101。
     代价：视频播放和窗口化游戏的合成效率略降（画面本身不受影响）。
     没崩过的电脑会自动跳过——没病不吃药。

  命令行执行：
    SmoothWinTray.exe --status   查看各项当前状态
    SmoothWinTray.exe --fix      应用（需管理员）
    SmoothWinTray.exe --restore  还原（需管理员）


开机自动启动（推荐）
--------------------
  命令行执行：
    SmoothWinTray.exe --install     开启（需管理员，只需做一次）
    SmoothWinTray.exe --uninstall   关闭

  原理：注册一个「登录时运行、最高权限」的计划任务
  （SmoothWinTray-AutoStart），开机不弹 UAC 授权框，延迟 30 秒启动，
  避开开机高峰。也可以在托盘菜单「设置…」里勾选。

  这个计划任务是用自定义模板注册的，不是 schtasks 的默认模板。
  因为默认模板自带几条会「把任务直接杀掉」的设置：
    · 运行 72 小时后停止任务             → 自定义模板改成「无时间上限」
    · 切换到电池供电就停止任务           → 改成 false
    · 空闲状态结束就停止任务             → 改成 false
    · 允许强制终止任务 AllowHardTerminate → 改成 false
  被任务计划程序服务强杀的进程不写应用日志、不留崩溃记录，表现就是
  「托盘图标悄悄没了，什么都没记」——这正是要避免的。
  另外加了「失败后 1 分钟自动重启，最多 3 次」。

  自愈看门狗（本版新增）：计划任务里还有一条「每 5 分钟触发一次」的定时触发器。
  托盘正常运行时，新实例会被单实例锁挡住并立刻退出（不占内存、不弹窗）；
  万一托盘被外部强杀（任务管理器结束进程、被别的清理软件误杀、假死卡住），
  下一个 5 分钟触发点就会自动把它拉回来——不需要重启电脑，也不需要人工干预。
  如果旧实例是「假死」（进程还在但消息循环已经停了、心跳不再更新），
  新实例会先把它结束掉再自己接管，避免锁死在一个永远不会恢复的进程上。

  停摆自愈（本版新增）：上面那条只管「进程被杀」。还有一种更隐蔽的情况——
  进程还活着，但界面和定时器全停了（被卡住、消息循环停摆）。这时单实例锁
  还被占着，外面怎么拉都拉不起来。所以程序内部自己起了一个看门狗线程：
  每 60 秒左右检查一次自己的心跳还新不新，一旦发现心跳超过 3 分钟没更新，
  就主动退出，让上面那条「每 5 分钟触发」的计划任务把自己重新拉起来。
  两种情况（被杀 / 卡住）现在都能自己恢复，都不用重启电脑。

  为什么会「悄悄消失」（已查清）：Windows 的作业对象（Job Object）可以「关掉就
  连子孙进程一起杀」，这种杀法不写应用日志、不留崩溃记录、事件日志里也查不到，
  表现就是进程凭空没了。如果托盘是从某个会自我清理的自动化脚本里启动的，脚本
  一退出，托盘就会被一起带走。所以：请始终用计划任务（开机自启 / --install 注册的
  那个）来启动它，不要从临时脚本里 Start-Process 启动——从计划任务启动时它的父
  进程是 svchost（任务计划程序服务），不属于任何临时作业对象，谁也带不走它。

  心跳日志：数据目录下的 heartbeat.log，每分钟一行「alive pid=… 采样次数=…
  工作集=… 线程=…」。它的用途是「事后取证」——托盘如果哪天又悄悄没了，
  看最后一行的时间就能知道它是哪一分钟消失的、消失前内存和线程是否正常
  （正常退出会写「正常退出」，被强杀则直接断在 alive 行）。


命令行模式（可选，适合批处理/其他电脑）
----------------------------------------
  SmoothWinTray.exe --report      打印一屏系统状态报告
  SmoothWinTray.exe --trim        立刻整理一次内存
  SmoothWinTray.exe --selftest    自检（权限、计数器、事件日志、目录可写等）
  SmoothWinTray.exe --status      查看 5 项系统优化状态
  SmoothWinTray.exe --fix         应用系统优化
  SmoothWinTray.exe --restore     还原系统优化
  SmoothWinTray.exe --install     开启开机自启
  SmoothWinTray.exe --uninstall   关闭开机自启
  SmoothWinTray.exe --devices     扫描驱动有问题的设备 + 挂起重启

  SmoothWinTray.exe --apps        列出所有后台应用及其子进程（文本版，按内存排序）

  说明：--report 是「一次性进程」，进程级 CPU/磁盘速率要靠两次采样的
  差值算，所以它内部会先预热 1.5 秒再出报告，启动稍慢属正常。

  可加 --out <文件> 指定输出位置；默认输出到 <数据目录>\cli-<模式>.txt

  另外有几个自检模式（一般用不到）：
    --uicheck      量一次状态窗口的构建与刷新耗时 + 排版自检 + 详细报告选中自检
    --startupui    打印自启项表格内容 + 启用/禁用注册表往返自检
    --leaktest     打印「增长提醒忽略名单」的读写与自动静音判定结果
    --settingshot  打印阈值自动/手动判定结果，并把设置窗口截一张图到
                   <数据目录>\settings-preview2.png
    --startupshot  把自启项窗口截一张图到 <数据目录>\startup-preview.png
    --appsui       打印后台应用窗口内容 + 按 PID 关子进程 / 整组关 / 系统进程保护自检
    --appsshot     把后台应用窗口截一张图到 <数据目录>\apps-preview.png
    --quitstate    查看「手动退出」记录还在不在（不启动托盘）
    --quit         让正在运行的托盘按「手动退出」正常退出（不杀进程）


程序和数据放在哪
----------------
  程序本体： C:\Users\<你>\AppData\Local\SmoothWin\SmoothWinTray.exe
    （本机就是这么装的，计划任务 SmoothWinTray-AutoStart 指向这个路径；
      想换地方，把 exe 拷过去再跑一次 --install 即可。）

  数据文件也在同一个目录： C:\Users\<你>\AppData\Local\SmoothWin\
     history.csv        内存历史（每 5 分钟一行，可用 Excel 打开）
     proc-baseline.csv  进程快照基线（用于增长对比）
     SmoothWinTray.log  运行日志（超过 1MB 自动轮转）
     heartbeat.log      心跳日志（每分钟一行 alive pid=… 采样次数=…）
     tray-config.ini    配置
     sysfix-backup.ini  系统设置原始值备份
     cli-*.txt          命令行模式的输出

  如果那个目录不可写（极少数受限环境），会自动依次回退到
     <exe所在目录>\SmoothWinData\  然后  %TEMP%\SmoothWin\
  实际用的是哪个，日志第一行「数据目录=…」会写明。


怎么确认它真的在工作
--------------------
  1. 托盘图标在（绿色/黄色/红色）
  2. 打开状态窗口，看四张指标卡的数字在动（可用内存 / 提交 / 换页压力 / 负载）
  3. 打开 history.csv，看是不是每 5 分钟多一行
  4. 打开 SmoothWinTray.log，触发整理时会写一行：
       [内存压缩 2538MB] 整理 16 个进程，失败 0，可用内存 29017→30717 MB (+1700)
  5. 状态窗口左下「系统设置」会显示设备驱动、挂起重启两行状态


想彻底删掉它
------------
  1. SmoothWinTray.exe --uninstall    （删掉开机自启计划任务）
  2. SmoothWinTray.exe --restore      （还原 5 项系统设置，需管理员）
  3. 托盘右键 → 退出
  4. 删掉 SmoothWin 文件夹和 %LOCALAPPDATA%\SmoothWin 文件夹


常见问题
--------
Q: 整理内存会不会把我正在用的程序弄卡？
A: 不会。只对后台闲置进程调用 EmptyWorkingSet，前台窗口和系统关键
   进程全部跳过。被整理的程序下次被访问时，Windows 会按需重新读回
   页面，只是慢一丁点，不会丢数据、不会崩溃。

Q: 整理内存能解决所有卡顿吗？
A: 不能。它只解决「内存被闲置程序占着不放」这一类。如果「实时压力」
   里的硬缺页一直很低、DPC 却很高，那卡顿来自驱动层，整理内存帮不上，
   得从驱动/硬件那边查。程序把这两类分开显示，就是为了让你别猜。

Q: 它弹通知说内存/CPU/磁盘有问题，可那些程序我还要用，怎么办？
A: 不用关。点一下那条通知，会打开状态窗口，最上面就是「不关也能缓解」
   的具体步骤——CPU 型教你调低后台任务优先级（任务照跑）、磁盘型教你
   把更新/网盘/下载/杀毒扫描暂停（不是关）、内存型告诉你判断标准是
   「可用内存」以及谁在变大就把它重启一次。
   如果你不想收到任何通知：设置里关掉「压力提醒」和「增长提醒」。

Q: 我天天开着 node / firefox / 编辑器，它老提醒我「这个程序在变大」？
A: 不用关它，也不用理它。这类程序越用越大本来就正常，程序现在有两条
   出路，都很快：
     ① 点一下那条气泡 → 问「以后不再提醒它吗」→ 点「是」，以后彻底安静；
     ② 什么都不点也行：同一个程序提醒满 3 次（默认值，设置里可改）后，
        它会自己写进「增长提醒忽略名单」，以后不再打扰。
   也可以在设置窗口的「增长提醒忽略名单」里直接填 node,firefox。
   ★ 它不会叫你关掉正在用的程序——这条是硬规矩。

Q: 它一直提示我 node / firefox 在用，烦不烦？
A: 新版已经不会了。四处都改了：
   ① CPU 阈值 90% → 95%，而且要求连续 12 次采样（约 1 分钟）都超标；
   ② 同一类提醒 30 分钟内只弹一次（旧版压力一解除就能马上再弹）；
   ③ 你正在用电脑（10 分钟内有键鼠操作）时不弹 CPU/磁盘型提醒，
      只在日志里记一笔，等你离开才提醒；
   ④ ★ 最关键的一条：就算你离开了电脑、CPU 或磁盘一直被占满，程序还会
      再看一眼「占着资源的是谁」——如果排第一的是你自己的程序（node、
      firefox、编译器、虚拟机…），说明那是你在干活，它只写一行日志，
      不会弹通知叫你关掉。只有当「系统进程」长期占满时才会提醒你。
      内存型不受这条限制：内存真见底时不管是谁在用、人在不在，都会提醒。
   增长提醒同理：阈值 200 → 500 MB/小时，并且要连续 3 次（约 15 分钟）
   都点名同一个程序才提醒——node / firefox 正常用着涨几百 MB/小时 是正常的。

Q: 状态窗口看着卡、点通知进去显示「未响应」？
A: 那是旧版的毛病，已经修好。原因是界面每秒都要重新生成整份报告
   （其中查事件日志一次要 300 毫秒，四次共 1.2 秒），把界面线程堵死了。
   现在改成：采样和拼装在后台线程做，界面只负责贴数字；事件日志结果
   缓存 10 分钟。实测界面最大停顿从约 1500 毫秒降到 79~125 毫秒。

Q: 「检查有问题的设备」报出好几个黄色感叹号，我能不管吗？
A: 能不管，但那样卡顿的根就一直留着。这些设备的驱动每次开机都会
   尝试加载、失败、再重试，并且系统会周期性重扫设备树。
   本机就有 9 个（这台机器上最典型的是缺芯片组驱动）。
   想处理的话：设备管理器 → 右键那一项 →「属性」→「详细信息」→
   选「硬件 ID」，把 VEN_ / DEV_ 记下来去搜，或到电脑/主板厂商的
   支持页面按机型找驱动，装完重启一次即可。
   装好之后回窗口点「重新检查」，那一行会变成「没有发现问题的设备」。

Q: 「自启项」窗口列了 26 项，我该关哪些？
A: 只关你「确实用不上」的。建议保留：远程控制类（向日葵 / RustDesk /
   UU远程）、安全软件、显卡相关、输入法。可以先关：各种更新器、
   助手、游戏平台、下载工具的常驻项。每关一项省下的内存，
   表格里已经标出来了，按占用从大到小挑就行——选中一行点
   「禁用自启」即可，不用再跑去任务管理器。想开回来就点「启用自启」。

Q: 报告里「系统负载」那行的 CPU 百分比准不准？
A: 准。性能计数器算的是「两次读数差值 ÷ 时间间隔」，背靠背连读两次
   会算出垃圾数字（早期版本就因为这个显示过 96.6%，而真实值是 29%）。
   现在已经强制两次有效读数至少隔 1 秒，间隔不够就沿用上一次的值，
   实测与系统自带计数器一致（38.5% vs 39.7%、33.6% vs 32.9%）。

Q: 它自己会不会反而拖慢系统？
A: 不会。早期版本采一次样要 3.8 秒（采样间隔才 5 秒），确实自己就是
   卡顿源。原因是用了 .NET 的 Process.TotalProcessorTime，本机 400 多个
   进程要 7 秒。现已改用原生 API GetProcessTimes，同样的数据只要
   30 毫秒左右，整轮采样从 3820 毫秒降到 32 毫秒（约 120 倍）。

Q: 它为什么不像别的优化软件一样，一有压力就弹窗让我「一键优化」？
A: 因为那正是你不需要的东西。能自动做的它已经做了（深度整理、恢复
   待机后整理），只有它真的做不到的时候才会打扰你——比如压力来自
   某个驱动，普通程序无权也不会去动驱动，只能由你决定怎么处理。

Q: 提示「需要管理员权限」怎么办？
A: 右键 SmoothWinTray.exe →「以管理员身份运行」；或托盘菜单选
   「以管理员身份重新启动」。日常监控和整理内存不需要管理员权限。

Q: 我点了「退出」，它会不会过 5 分钟又自己回来？
A: 不会。点「退出」时它会在数据目录里留一张「手动退出记录」，
   计划任务到点拉起的新实例看到这张记录会立刻静默退出，不占内存、
   不弹窗。下次你自己双击启动（或重启电脑后）记录自动失效，一切照旧。
   想确认记录状态：SmoothWinTray.exe --quitstate

Q: 关了快速启动，开机会不会变慢很多？
A: 会慢几秒到十几秒，这是换取「关机真正清干净内核状态」的必要代价。
   不想接受就用 --restore 还原。

Q: 它和 360 / 火绒 / Wise Memory Optimizer 冲突吗？
A: 不冲突，它不注入进程、不装驱动。但请不要同时用多个「内存优化」
   工具，效果会互相抵消。
